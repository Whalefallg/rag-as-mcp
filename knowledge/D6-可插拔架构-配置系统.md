## D6.1 工厂模式全景：五大工厂

### 全景图

```
config/settings.yaml
        ↓ load_settings()
   Settings 对象
        ↓
┌───────────────────────────────────────────────────────┐
│  工厂层（Factory Pattern）                             │
│                                                       │
│  LLMFactory.create()         → BaseLLM 实现           │
│  EmbeddingFactory.create()   → BaseEmbedding 实现     │
│  RerankerFactory.create()    → BaseReranker 实现      │
│  VectorStoreFactory.create() → BaseVectorStore 实现   │
│  EvaluatorFactory.create()   → BaseEvaluator 实现     │
└───────────────────────────────────────────────────────┘
        ↓
   业务代码只依赖抽象接口，不知道具体实现
```

### 工厂注册机制（装饰器模式）

```python
# 工厂维护一个注册表
_REGISTRY: Dict[str, Type[BaseReranker]] = {}

def register_reranker(name: str):
    def decorator(cls):
        _REGISTRY[name] = cls
        return cls
    return decorator

# 具体实现在定义时自动注册
@register_reranker("cross_encoder")
class CrossEncoderReranker(BaseReranker): ...

@register_reranker("llm")
class LLMReranker(BaseReranker): ...

# 工厂创建
def create_reranker(settings: Settings) -> BaseReranker:
    backend = settings.rerank.backend
    cls = _REGISTRY.get(backend)
    if cls is None:
        raise ValueError(f"未知 reranker backend: {backend}")
    return cls(model=settings.rerank.model)
```

装饰器注册的好处：新增后端只需添加一个文件 + 一个装饰器，工厂代码不需要修改。

### 五大工厂职责

| 工厂 | 抽象接口 | 当前默认实现 | 可替换选项 |
|------|---------|-----------|----------|
| LLMFactory | `BaseLLM` | DeepSeek | Azure / OpenAI / Ollama |
| EmbeddingFactory | `BaseEmbedding` | SiliconFlow(BGE-M3) | Azure / Ollama |
| RerankerFactory | `BaseReranker` | NoneReranker | CrossEncoder / LLM |
| VectorStoreFactory | `BaseVectorStore` | ChromaStore | Qdrant / Pinecone |
| EvaluatorFactory | `BaseEvaluator` | CustomEvaluator | Ragas / DeepEval |

## D6.2 settings.yaml 配置结构与 Settings 类加载机制

### 配置文件结构

```yaml
llm:
  provider: deepseek          # 切换 LLM Provider
  model: deepseek-chat
  api_key: "sk-..."

embedding:
  provider: openai            # 用 openai 接口适配 SiliconFlow
  model: BAAI/bge-m3
  api_key: "sk-..."
  base_url: "https://api.siliconflow.cn/v1"

vector_store:
  backend: chroma
  persist_path: ./data/db/chroma

splitter:
  method: recursive
  chunk_size: 1000
  chunk_overlap: 200

retrieval:
  sparse_backend: bm25
  fusion_algorithm: rrf
  top_k_dense: 20
  top_k_sparse: 20
  top_k_final: 10

rerank:
  backend: none               # 关闭精排（none / cross_encoder / llm）
  top_m: 30
```

### Settings 加载流程

```python
def load_settings(config_path="config/settings.yaml") -> Settings:
    # 1. 读取 YAML
    config = yaml.safe_load(open(config_path))

    # 2. 解析为强类型 dataclass（IDE 自动补全，拼写错误编译时暴露）
    settings = Settings(
        llm=LLMConfig(...),
        embedding=EmbeddingConfig(...),
        ...
        raw_config=config    # 保留原始 dict，供读取自定义扩展字段
    )

    # 3. 启动时立刻校验（fail-fast）
    validate_settings(settings)
    return settings
```

### raw_config 的用途

`raw_config` 保存原始 YAML dict，让各模块读取 schema 之外的配置字段而不需要预先在 Settings 中声明：

```python
# 读取 ingestion.chunk_refiner.use_llm（非 Settings 字段）
use_llm = settings.raw_config.get("ingestion", {}).get("chunk_refiner", {}).get("use_llm", False)
```

### validate_settings 的价值

```python
def validate_settings(settings: Settings) -> None:
    if settings.llm.provider not in ['azure', 'openai', 'ollama', 'deepseek']:
        raise ValueError(f"不支持的 LLM provider: {settings.llm.provider}")
    if settings.splitter.chunk_overlap >= settings.splitter.chunk_size:
        raise ValueError("chunk_overlap 必须小于 chunk_size")
    ...
```

配置错误在**启动时**就报错（而非运行到相关代码时才崩溃），大幅缩短调试时间。

## D6.3 LLM Provider 多厂商支持：切换逻辑

### 统一抽象接口

```python
class BaseLLM(ABC):
    @abstractmethod
    def chat(self, messages: List[Dict[str, str]]) -> str:
        """messages 格式：[{"role": "user", "content": "..."}]"""
        pass
```

上层调用 `llm.chat(messages)` 即可，不关心底层是 Azure、OpenAI 还是 Ollama。

### 各 Provider 实现差异（封装在具体类内部）

| Provider | 认证方式 | 请求格式差异 |
|----------|---------|-----------|
| OpenAI | `Authorization: Bearer {api_key}` | 标准 OpenAI Chat API |
| Azure OpenAI | `api-key` header + `api-version` 参数 | endpoint + deployment_name 替代 model |
| DeepSeek | `Authorization: Bearer {api_key}` | OpenAI 兼容格式，`base_url` 不同 |
| Ollama | 无认证 | 本地 HTTP API，`/api/chat` 端点 |

### OpenAI 兼容模式

DeepSeek、SiliconFlow 等厂商提供 OpenAI 兼容 API，只需设置 `base_url`：

```yaml
embedding:
  provider: openai            # 骗框架用 openai 接口
  base_url: "https://api.siliconflow.cn/v1"  # 实际指向 SiliconFlow
  model: BAAI/bge-m3
```

这是"OpenAI 兼容协议"的工程价值：一套代码，适配十几家厂商。

## D6.4 Embedding Provider 抽象：多后端实现对比与选型策略

### BaseEmbedding 接口

```python
class BaseEmbedding(ABC):
    @abstractmethod
    def embed(self, texts: List[str], trace=None) -> List[List[float]]:
        """批量编码，返回向量列表（维度取决于模型）"""
        pass
```

### 各 Provider 对比

| Provider | 模型 | 维度 | 特点 |
|----------|------|------|------|
| OpenAI | text-embedding-3-small | 1536 | 质量好，按 token 收费 |
| SiliconFlow | BAAI/bge-m3 | 1024 | 免费额度大，多语言旗舰 |
| Azure | text-embedding-ada-002 | 1536 | 企业合规，Azure 生态 |
| Ollama | nomic-embed-text | 768 | 完全本地，无费用，速度快 |

### 选型策略

- **开发调试**：Ollama 本地模型，零成本，无网络依赖
- **中文内容**：BAAI/bge-m3（BGE 系列对中文优化最好）
- **企业生产**：Azure（合规 + 数据不出境）
- **英文技术文档**：OpenAI text-embedding-3-large（质量最高）

## D6.5 Base 类设计哲学：接口抽象、继承层次与扩展点

### 设计原则

**接口隔离（Interface Segregation）**：每个 Base 类只定义最小化接口，避免"胖接口"迫使实现类实现无关方法。

```python
class BaseEmbedding(ABC):
    def embed(self, texts, trace=None): ...   # 核心接口：1 个方法

class BaseVectorStore(ABC):
    def upsert(self, records, trace=None): ...
    def query(self, vector, top_k, filters, collection): ...
    def get_by_ids(self, ids): ...
    def delete_by_metadata(self, filter): ...   # DocumentManager 用
```

### 继承层次示例（LLM）

```
BaseLLM（抽象）
    ├── OpenAILLM（OpenAI 官方 API）
    │       └── AzureLLM（继承 OpenAI，覆盖认证和 endpoint）
    ├── DeepSeekLLM（OpenAI 兼容格式）
    └── OllamaLLM（本地 HTTP API）

BaseVisionLLM（抽象，继承 BaseLLM 思路）
    └── AzureVisionLLM（GPT-4o Vision）
```

### 扩展新 Provider 的步骤

1. 创建 `src/libs/llm/my_llm.py`，继承 `BaseLLM`，实现 `chat()`
2. 在 `llm_factory.py` 中注册：`@register_llm("my_provider")`
3. 在 `settings.yaml` 中添加 `provider: my_provider`
4. 在 `validate_settings` 中加入 `"my_provider"` 到合法列表

**零业务代码修改**，框架其余部分自动适配。

## D6.1 Factory Pattern Overview: Five Factories

```
config/settings.yaml
        ↓ load_settings()
   Settings object
        ↓
  LLMFactory.create()          → concrete BaseLLM
  EmbeddingFactory.create()    → concrete BaseEmbedding
  RerankerFactory.create()     → concrete BaseReranker
  VectorStoreFactory.create()  → concrete BaseVectorStore
  EvaluatorFactory.create()    → concrete BaseEvaluator
```

Business code only depends on abstract interfaces — never on concrete implementations.

### Decorator-Based Registration

```python
_REGISTRY: Dict[str, Type[BaseReranker]] = {}

def register_reranker(name: str):
    def decorator(cls):
        _REGISTRY[name] = cls
        return cls
    return decorator

@register_reranker("cross_encoder")
class CrossEncoderReranker(BaseReranker): ...
```

Adding a new backend = new file + one decorator. The factory itself never needs to change.

## D6.2 settings.yaml Structure and Settings Loading Mechanism

### Loading Flow

```python
def load_settings(config_path) -> Settings:
    config = yaml.safe_load(open(config_path))      # 1. read YAML
    settings = Settings(llm=LLMConfig(...), ...)    # 2. parse into typed dataclasses
    validate_settings(settings)                     # 3. fail-fast at startup
    return settings
```

**Why dataclasses over plain dicts**: IDE autocomplete catches typos at development time, not at runtime.

**`raw_config`**: the original YAML dict is stored alongside the typed fields, allowing modules to read custom extension keys (e.g. `ingestion.chunk_refiner.use_llm`) without pre-declaring them:

```python
use_llm = settings.raw_config.get("ingestion", {}).get("chunk_refiner", {}).get("use_llm", False)
```

**`validate_settings`** runs at startup and raises `ValueError` with the exact field path (e.g. `"unsupported rerank backend: foo"`), making misconfiguration errors fast to diagnose.

## D6.3 LLM Provider Multi-Vendor Support

### Unified Interface

```python
class BaseLLM(ABC):
    @abstractmethod
    def chat(self, messages: List[Dict[str, str]]) -> str: ...
```

Callers always write `llm.chat(messages)` — never anything provider-specific.

### OpenAI-Compatible Protocol

DeepSeek, SiliconFlow, and many other vendors expose an OpenAI-compatible API. Setting `base_url` in the config is enough to redirect the same OpenAI client code to a different backend:

```yaml
embedding:
  provider: openai
  base_url: "https://api.siliconflow.cn/v1"   # points to SiliconFlow, not OpenAI
  model: BAAI/bge-m3
```

## D6.5 Base Class Design Philosophy: Interface Abstraction, Inheritance, Extension Points

**Interface Segregation**: each base class exposes the minimum interface needed. Implementors are not forced to implement unrelated methods.

**Four steps to add a new provider**:
1. Create `src/libs/llm/my_llm.py`, extend `BaseLLM`, implement `chat()`.
2. Add `@register_llm("my_provider")` decorator.
3. Set `provider: my_provider` in `settings.yaml`.
4. Add `"my_provider"` to the allowed list in `validate_settings`.

Zero changes to any business code.
