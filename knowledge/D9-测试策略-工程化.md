## D9.1 测试分层策略：Unit / Integration / E2E 各层覆盖范围

## D9.2 Test Fixtures 与 conftest.py：Mock 策略与测试数据管理

### Mock 策略

**外部依赖全 mock，业务逻辑真实运行：**

```python
# 单元测试：mock 外部调用，测试编排逻辑
@pytest.fixture
def fake_embedding():
    mock = MagicMock()
    mock.embed.return_value = [[0.1, 0.2, 0.3] * 512]  # 稳定向量
    return mock

@pytest.fixture
def fake_vector_store():
    mock = MagicMock()
    mock.query.return_value = [
        {"id": "chunk_001", "score": 0.9, "text": "测试内容", "metadata": {}}
    ]
    return mock

def test_dense_retriever(fake_embedding, fake_vector_store):
    retriever = DenseRetriever(settings, fake_embedding, fake_vector_store)
    results = retriever.retrieve("测试查询", top_k=5)
    assert len(results) > 0
    assert results[0].chunk_id == "chunk_001"
```

### 关键 Fixture 设计原则

- **临时目录隔离**：集成测试使用 `tmp_path`（pytest 内置），测试结束后自动清理
- **Fake 实现优先于 Mock**：纯逻辑的 Fake（如 `FakeSplitter` 总返回固定切分）比 `MagicMock` 更稳定
- **deterministic 数据**：测试用 PDF 内容固定，golden_test_set.json 中 expected_chunk_ids 经过验证

### conftest.py 结构

```python
# tests/conftest.py
@pytest.fixture(scope="session")
def settings():
    return load_settings("config/settings.yaml")

@pytest.fixture
def temp_chroma(tmp_path):
    """每个测试用独立的临时向量库"""
    cfg = VectorStoreConfig(backend="chroma", persist_path=str(tmp_path))
    return ChromaStore(cfg)
```

## D9.4 脚本入口设计：四大脚本的职责边界与参数化设计

### 脚本职责矩阵

| 脚本 | 职责 | 调用的核心模块 |
|------|------|-------------|
| `scripts/ingest.py` | 离线文档摄取 | `IngestionPipeline.run()` |
| `scripts/query.py` | 在线查询调试 | `HybridSearch.search()` + `Reranker.rerank()` |
| `scripts/evaluate.py` | 评估运行 | `EvalRunner.run()` + `CompositeEvaluator` |
| `scripts/start_dashboard.py` | 启动 Streamlit | `streamlit run src/observability/dashboard/app.py` |

### 设计原则：脚本≠业务逻辑

脚本只做三件事：
1. 解析 CLI 参数（`argparse`）
2. 初始化组件（`load_settings + Factory.create()`）
3. 调用 Core/Ingestion 层的入口函数

业务逻辑不放在脚本里，保证 Dashboard、测试、CLI 可以复用同一套 Core 层逻辑。

### ingest.py 参数设计

```bash
python scripts/ingest.py \
  --path data/documents/default/   # 文件或目录
  --collection default             # 目标集合
  --force                          # 忽略完整性检查，强制重新摄取
```

### query.py 参数设计（--verbose 的调试价值）

```bash
python scripts/query.py \
  --query "如何配置 Azure OpenAI？" \
  --top-k 10 \
  --collection default \
  --verbose      # 显示各阶段中间结果（Dense Top-20 / Sparse Top-20 / Fusion / Rerank）
  --no-rerank    # 跳过 Reranker，直接返回 RRF 结果（对比实验）
```

`--verbose` 模式直接对应 Dashboard 的 Query 追踪页面，让开发者在命令行就能看到完整的检索链路。

## D9.2 Test Fixtures and Mock Strategy

### Mock Philosophy

**Fake over Mock**: a `FakeSplitter` that always returns a fixed split is more stable and readable than a `MagicMock` — it behaves like a real object without the fragility of call-count assertions.

```python
@pytest.fixture
def fake_embedding():
    mock = MagicMock()
    mock.embed.return_value = [[0.1] * 512]   # deterministic vector
    return mock

def test_dense_retriever(fake_embedding, fake_vector_store):
    retriever = DenseRetriever(settings, fake_embedding, fake_vector_store)
    results = retriever.retrieve("test query", top_k=5)
    assert results[0].chunk_id == "chunk_001"
```

### Key Fixture Principles

- **`tmp_path` isolation**: integration tests use pytest's built-in `tmp_path` — each test gets its own temp directory, cleaned up automatically.
- **Deterministic data**: test PDFs have fixed content; `golden_test_set.json` expected IDs are pre-verified.
- **`conftest.py`**: shared fixtures (`settings`, `temp_chroma`) are defined here and auto-discovered by pytest.

## D9.4 Script Entry Design: Responsibility Boundaries

### Scripts Do Exactly Three Things

1. Parse CLI arguments (`argparse`)
2. Initialize components (`load_settings` + `Factory.create()`)
3. Call a Core/Ingestion layer entry function

**No business logic lives in scripts.** This ensures the Dashboard, tests, and CLI can all reuse the same Core layer code without duplication.

### Notable Flag Design

| Script | Flag | Value |
|--------|------|-------|
| `ingest.py` | `--force` | Skip SHA256 check; force full re-ingestion |
| `query.py` | `--verbose` | Show intermediate results from every stage (mirrors Dashboard Query Traces) |
| `query.py` | `--no-rerank` | Skip reranker; useful for A/B comparison against pure RRF ordering |

The `--verbose` flag in `query.py` is effectively a CLI version of the Dashboard's Query Traces page — both show dense Top-20, sparse Top-20, fusion result, and rerank result.
