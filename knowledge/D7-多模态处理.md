## D7.1 PDF 解析：PdfLoader 实现与 FileIntegrity 文件校验

### PDF 解析策略

采用 **MarkItDown** 将 PDF 转换为标准 Markdown 格式，而非直接提取纯文本。

**选 Markdown 的原因：**
- `RecursiveCharacterTextSplitter` 对 Markdown 结构（标题 `#`、段落、代码块）有天然适配性
- 标题层级保留，切分时不会把属于同一节的内容分到不同 chunk
- 与后续 Transform 阶段的 LLM 处理更兼容

### 图片提取与占位符机制

```
PDF 文件
  ↓ MarkItDown 解析
  ↓ 提取嵌入图片 → 保存到 data/images/{doc_hash}/{image_id}.png
  ↓ 在文本中图片原位插入占位符 [IMAGE: {image_id}]
  ↓
Document(
    text="...章节内容...[IMAGE: abc123_0_1]...更多内容...",
    metadata={
        "images": [
            {
                "image_id": "abc123_0_1",
                "path": "data/images/abc123/abc123_0_1.png",
                "page": 5,
                "seq": 1,
                ...
            }
        ]
    }
)
```

### FileIntegrity：SHA256 增量跳过

```python
class SQLiteIntegrityChecker:
    def compute_sha256(self, path: str) -> str: ...

    def should_skip(self, file_hash: str) -> bool:
        # 查询 ingestion_history.db：hash 已存在且 status='success' → True
        return db.query("SELECT status FROM ingestion_history WHERE file_hash=? AND status='success'", hash)

    def mark_success(self, file_hash: str, file_path: str): ...
    def mark_failed(self, file_hash: str, error_msg: str): ...
```

**增量摄取的零成本**：文件内容未变时（hash 相同），直接跳过，不调用任何 LLM，不重算向量，节省 100% 的计算成本。

**数据库位置：** `data/db/ingestion_history.db`（SQLite，WAL 模式，并发安全）

## D7.2 Vision LLM：Azure/OpenAI Vision 图片理解能力集成

### BaseVisionLLM 抽象接口

```python
class BaseVisionLLM(ABC):
    @abstractmethod
    def chat_with_image(
        self,
        text: str,
        image_path: str,   # 本地路径或 base64 字节
        trace=None,
    ) -> ChatResponse:
        """输入：文本 prompt + 图片，输出：文本描述"""
        pass
```

### AzureVisionLLM 实现要点

- **认证**：`azure_endpoint` + `api-key` header + `api-version` 参数
- **图片传递格式**：将本地图片读取为 bytes → Base64 编码 → 嵌入 message 的 `image_url.url`（`data:image/png;base64,...`）
- **自动压缩**：超过 `max_image_size`（默认 2048px）的图片先缩放再发送，减少 Token 消耗

### 双模型选型策略

| 场景 | 首选 | 备选 |
|------|------|------|
| 英文技术文档 / 复杂图表 | GPT-4o (Azure) | Qwen-VL-Max |
| 中文文档 / 中文截图 | Qwen-VL-Max (阿里云) | GPT-4o |
| 大批量处理 / 成本敏感 | Qwen-VL-Plus | Gemini Pro Vision |

## D7.3 ImageCaptioner：图片描述生成流程与 Prompt 模板设计

### 整体流程

```
Chunk（含 image_refs）
  ↓ 读取 chunk.metadata["images"] 中的 file_path
  ↓ 检查文件存在
  ↓ 读取图片 bytes
  ↓ 构建 Prompt（含 chunk 上下文前 500 字）
  ↓ Vision LLM.chat_with_image()
  ↓ caption 写入 metadata["images"][i]["caption"]
```

### Prompt 设计（`config/prompts/image_captioning.txt`）

```
Describe the content of this image concisely (2-3 sentences).
Focus on: diagrams/charts data, text visible in the image, and key visual elements.
Context from surrounding text: {context}
```

**上下文注入的价值**：把图片周围的文字一起发给 Vision LLM，帮助它理解图片在文档中的语境（如"这张图展示的是第三章提到的系统架构"），生成质量更高的描述。

### 降级机制

```python
def transform(self, chunks, trace=None):
    for chunk in chunks:
        image_refs = chunk.metadata.get("image_refs", [])

        # 降级条件：功能禁用 / 无图片 / Vision LLM 未配置
        if not self._enabled or not image_refs or self._vision_llm is None:
            if image_refs:
                chunk.metadata["has_unprocessed_images"] = True  # 标记未处理
            continue  # 不阻塞，继续处理下一个 chunk

        # 单图失败不影响其他图
        for img_info in images:
            try:
                caption = self._vision_llm.chat_with_image(prompt, img_path)
                img_info["caption"] = caption
            except Exception:
                chunk.metadata["has_unprocessed_images"] = True
                continue
```

**幂等性**：已有 caption 的图片可通过检查 `img_info.get("caption")` 跳过重复处理。

## D7.4 多模态 Chunk 存储与检索：ImageStorage 与 MultimodalAssembler 协同

### 双轨存储策略

| 存储 | 内容 | 用途 |
|------|------|------|
| ChromaDB | 含 caption 的 Chunk 文本 + 向量 | 语义检索 |
| 文件系统 | 原始图片文件（PNG/JPEG） | 返回给 Client 展示 |
| SQLite (`image_index.db`) | image_id → file_path 映射 | 快速查找图片路径 |

### ImageStorage

### 检索时的图文联动流程

```
用户查询 "系统架构是什么？"
    ↓ HybridSearch 命中 chunk（text 含 "系统采用三层架构... [图片描述: 展示了三层箭头图]"）
    ↓ ResponseBuilder 检查 chunk.metadata["image_refs"] = ["abc123_0_1"]
    ↓ ImageStorage.get_path("abc123_0_1") → "data/images/default/abc123_0_1.png"
    ↓ 读取文件 bytes → Base64 编码
    ↓ 构造 MCP 响应
        content[0] = {"type": "text", "text": "...系统采用三层架构...\n\n[1] arch.pdf"}
        content[1] = {"type": "image", "data": "<base64>", "mimeType": "image/png"}
```

### "图转文"策略的架构价值

不需要引入 CLIP 等多模态向量模型，不需要独立的图像向量库：
- **架构统一**：图片描述文本被纳入普通 Chunk，走相同的 Embedding → ChromaDB 链路
- **成本可控**：仅在 Ingestion 阶段一次性调用 Vision LLM，检索时零额外成本
- **检索透明**：用户用自然语言查询，命中的是文本描述，再附带返回对应图片

## D7.1 PDF Parsing: PdfLoader and FileIntegrity Check

**Why Markdown as intermediate format**: `RecursiveCharacterTextSplitter` has native affinity for Markdown structure (headings `#`, paragraphs, code blocks) — heading hierarchy is preserved, so semantically related content stays in the same chunk.

### Image Extraction and Placeholder Mechanism

```
PDF
  ↓ MarkItDown
  ↓ extract embedded images → save to data/images/{doc_hash}/{image_id}.png
  ↓ insert placeholder at original image position: [IMAGE: {image_id}]
  ↓
Document(
    text="...section text...[IMAGE: abc123_0_1]...more text...",
    metadata={"images": [{"image_id": "abc123_0_1", "path": "...", "page": 5, ...}]}
)
```

### FileIntegrity: SHA256 Incremental Skip

```python
def should_skip(self, file_hash: str) -> bool:
    # query ingestion_history.db: hash exists AND status='success' → True
```

If file content is unchanged (same hash), the entire pipeline is skipped — no LLM calls, no vector recomputation. **100% cost savings** for unchanged files.

**Database**: `data/db/ingestion_history.db` — SQLite in WAL mode (concurrent-safe).

## D7.3 ImageCaptioner: Caption Generation Flow and Prompt Design

### End-to-End Flow

```
Chunk (with image_refs)
  ↓ read file_path from chunk.metadata["images"]
  ↓ check file exists
  ↓ read image bytes
  ↓ build prompt (inject first 500 chars of chunk text as context)
  ↓ Vision LLM.chat_with_image()
  ↓ write caption → metadata["images"][i]["caption"]
```

**Context injection value**: sending the surrounding text alongside the image helps the Vision LLM understand the image's role in the document, producing higher-quality descriptions (e.g. "this diagram illustrates the three-layer architecture described in Chapter 3").

### Graceful Degradation

```python
if not self._enabled or not image_refs or self._vision_llm is None:
    if image_refs:

# single image failure doesn't affect other images

    chunk.metadata["has_unprocessed_images"] = True
```

## D7.4 Multimodal Storage and Retrieval: ImageStorage and MultimodalAssembler

### Dual-Track Storage

| Storage | Content | Purpose |
|---------|---------|---------|
| ChromaDB | Chunk text containing caption + dense vector | Semantic search |
| Filesystem | Raw image files (PNG/JPEG) | Return to client for display |
| SQLite (`image_index.db`) | `image_id → file_path` mapping | Fast path lookup |

### Retrieval-Time Image Linking Flow

```
User query: "What does the system architecture look like?"
  ↓ HybridSearch hits chunk (text includes "[Image: 3-layer architecture diagram...]")
  ↓ ResponseBuilder reads chunk.metadata["image_refs"] = ["abc123_0_1"]
  ↓ ImageStorage.get_path("abc123_0_1") → "data/images/default/abc123_0_1.png"
  ↓ read bytes → Base64 encode
  ↓ MCP response:
      content[0] = {"type": "text", "text": "The system uses a 3-layer architecture...\n\n[1] arch.pdf"}
      content[1] = {"type": "image", "data": "<base64>", "mimeType": "image/png"}
```

### Architectural Value of "Image-to-Text" Strategy

No need for CLIP or a separate image vector store:
- **Unified architecture**: image captions become ordinary text chunks, flowing through the same Embedding → ChromaDB pipeline.
- **Cost-controlled**: Vision LLM is called only once at ingestion time; zero extra cost at query time.
- **Transparent retrieval**: users query in natural language, hit the text description, and receive the corresponding image as a bonus.
